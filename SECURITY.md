# Security policy

## Reporting a vulnerability

Please use GitHub's private vulnerability reporting for the Crewhelm repository. Do not open a
public issue or discussion for an undisclosed vulnerability.

Include the affected component, reproduction steps, expected impact, and any known mitigation.
Avoid including live credentials or personal data.

If private reporting is temporarily unavailable, open a public issue containing no vulnerability
details and ask the maintainer to establish a private contact channel.

## Supported versions

Crewhelm has not published a production release. Security fixes currently target the `main`
branch. A version support policy will be published before the first stable release.

## Security expectations

Crewhelm does not accept known authentication bypasses, authorization bypasses, secret exposure,
unbounded agent execution, unrestricted network egress, or unsigned executable marketplace
content as deferred work.
